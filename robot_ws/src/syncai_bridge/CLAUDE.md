# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

**syncai_bridge** is a Go service that subscribes to ROS 2 DDS topics (via CycloneDDS C bindings through CGo) and makes robot state data available to non-ROS backend services. It lives inside the `robot_ws` colcon workspace but is excluded from colcon builds via `COLCON_IGNORE`.

## Build Commands

```bash
# Requires CycloneDDS headers/libs from ROS 2 Jazzy
source /opt/ros/jazzy/setup.bash

# Build
CGO_ENABLED=1 go build -o syncai-bridge ./cmd/bridge

# Run
ROBOT_ID=robot01 ./syncai-bridge
```

CGo links against CycloneDDS at `/opt/ros/jazzy/lib/aarch64-linux-gnu` (aarch64). The `CFLAGS`/`LDFLAGS` are hardcoded in `internal/dds/cyclonedds.go`. For x86_64, these paths must be adjusted.

## Architecture

```
cmd/bridge/main.go          — Entry point: creates DDSBridge, registers callback, waits for signal
internal/
  bridge/bridge.go          — Protocol-agnostic Bridge interface + BaseBridge (thread-safe callbacks, status)
  dds/
    bridge.go               — DDSBridge: implements Bridge using CycloneDDS participant/topic/reader
    cyclonedds.go           — CGo bindings: C helper functions + Go wrappers for DDS entities
    callback.go             — Global reader registry + //export goOnDataAvailable (C→Go callback)
    types.go                — RobotState Go struct (JSON-serializable domain model)
    robot_state_ros2.{idl,h,c} — IDL-generated C types for syncai_common/msg/RobotState
```

### Key Design Patterns

- **Bridge interface** (`internal/bridge`): Protocol abstraction (`Connect`, `Disconnect`, `OnData`, `HealthCheck`). Designed for future protocols (MQTT, MODBUS) alongside DDS.
- **C→Go callback flow**: CycloneDDS listener fires `on_data_available_cb` (C) → `goOnDataAvailable` (Go, via `//export`) → looks up `DDSBridge` in global `readerRegistry` by reader handle → calls `onDataAvailable()` → `EmitData()` to all registered callbacks.
- **Global reader registry** (`callback.go`): Maps DDS reader handles (int32) to `*DDSBridge` instances because C function pointers cannot carry Go closure context. Protected by `sync.RWMutex`.
- **DDS topic naming**: Defaults to `rt/<namespace>/robot_state` (ROS 2 DDS wire format uses `rt/` prefix).

### IDL / Generated Code

The `.idl`, `.h`, and `.c` files in `internal/dds/` are generated by the CycloneDDS IDL compiler from `syncai_common/msg/RobotState.msg`. If `RobotState.msg` changes upstream:

```bash
# Regenerate from the IDL file
idlc -l c robot_state_ros2.idl
```

Then update the Go `RobotState` struct in `types.go` and the field mappings in `TakeRobotState()` (`cyclonedds.go`).

## Data Flow

```
ROS 2 (syncai_robot_state) publishes /robot_state on DDS
    → CycloneDDS listener callback (C thread)
    → goOnDataAvailable → DDSBridge.onDataAvailable()
    → TakeRobotState (C→Go struct conversion)
    → JSON marshal → EmitData → registered callbacks
```

## QoS Configuration

The DDS reader uses BEST_EFFORT reliability, VOLATILE durability, KEEP_LAST(5) history — matching typical ROS 2 sensor/state publisher defaults. Configured in `create_reader_with_listener()` in `cyclonedds.go`.
